# HomeClaim Runtime Readiness Inventory

Snapshot: 2026-10-11, after the user-path, recovery, legacy, and runtime follow-up in this checkout.

This document records the observed code and runtime wiring. It is not a feature promise. A class, schema, or test alone does not make a user-facing function active. Re-check the current runtime path before relying on this snapshot.

## Status vocabulary

- `IMPLEMENTED_AND_ACTIVE`: registered in the current runtime and has a user or server entry point.
- `IMPLEMENTED_BUT_PARTIAL`: active, with known behavior or recovery gaps.
- `IMPLEMENTED_BUT_NOT_WIRED`: implementation exists but the current runtime has no entry point to it.
- `LEGACY_ONLY`: retained for source/data compatibility, not the canonical active path.
- `PLACEHOLDER`: a model, key, stub, or declared route without working product behavior.
- `DEAD_CODE`: no current callers or registration were found; remove only after checking compatibility.
- `MISSING_BUT_REQUIRED_FOR_EXISTING_FEATURE`: required behavior for an already exposed function is absent or unsafe.

Known adapter shortcuts remain: REST uses one server admin-token actor rather than per-user principals, and the role GUI deliberately limits new assignments to online Paper players because no authoritative offline identity resolver is configured. Actorless role and administrative mutation adapters, the unused direct `JdbcRoleRepository`, and the unconnected PlotMember service/repository were removed. `PolicyActionRequest` and the unregistered Bukkit import/command executor adapters were removed. `Decision.allowed` and its Boolean constructor were removed because there was no current internal caller or published core API contract; active policy, protection, REST mapping, and tests use `DecisionEffect`. Selected string-world DTO/config/platform fields remain explicit compatibility boundaries.

`PendingConfirmationStore` is a small volatile, actor/operation/target/state-bound primitive for a future destructive command. It expires entries and consumes them once; no `/plot confirm` command is registered yet because this checkout has no destructive command producer. It is deliberately not a durable workflow or resume mechanism.

## Technical remaining work

This inventory describes current technical behavior and open work.

### MUST FIX FOR CORE FUNCTIONALITY

- No reproducible false-success defect was found in the actor-aware role, entry-deny, flag, limit, profile, price, or component paths reviewed in this follow-up. The operation services now return structured results and record terminal audit states when configured with the shared sink.
- This snapshot contains no newly confirmed immediate defect in the reviewed mutation paths. Add items here only when a reproducible correctness, persistence, protection, or authorization defect is confirmed.

### SHOULD FIX SOON

- Reset and merge/unlink recovery is visible and correlated, but interrupted or partial world changes cannot be safely resumed or automatically undone. `/plot jobs inspect <job-id>` shows the persisted recovery-required job, its regions, world/area, backend, progress, correlation, timestamp, and failure summary. Operators must inspect affected regions and run a new explicit safe operation or manually repair; there is no automatic resume, acknowledgement state, or durable block snapshot.
- The role GUI only selects currently online players. An offline identity lookup can be added later only with an authoritative server-side source; HomeClaim does not derive UUIDs from names.
- There is no REST component mutation route. Existing component mutations are GUI-only.
- The connected-player workflow has not been exercised. The local environment had no compatible Paper 26.3 client; server startup, command registration, command-tree tests, and database tests do not validate live inventory clicks or player-to-player protection behavior.

- Existing-world conversion requires FAWE. Keep that operation-specific requirement clear in setup help and documentation; ordinary runtime, claims, protection, and native resets work without FAWE.

- Home/Visit remain unverified with a connected player. Paper and Purpur startup, the current command tree, SQLite initialization, and clean shutdown were smoke-tested against the rebuilt shaded artifact.

### TECHNICAL DEBT

- The lifecycle Brigadier command tree is the only active Paper registration path. Dormant Bukkit `onCommand` / `onTabComplete` adapters and the unused generic executor bridge were removed; sender wrappers remain for the core audit command adapter.
- The unreferenced `RegionVisualizerImpl` was removed. The current plugin has no region-boundary particle visualization feature.
- Core `Position` and resolved `ActionRequest` endpoints now use the HomeClaim `WorldId`; Paper UUIDs are translated through the stored platform binding before policy evaluation. The active Zone command/GUI and Paper mutation/reset lookup use `AreaId`/WorldId and UUID-first resolution.
- String-valued world names remain in deprecated Region/Zone display and persistence adapters, REST request/response DTOs, the API client's distinct stable-string ID representation, inactive import data, config filenames/references, and the Paper mutation backend's world-name boundary after resolving a Paper `World`. `Region.world`, `Zone.world`, and `Position(String, ...)` are compatibility/display adapters, not canonical identity.
- The client API module still has a string-valued `WorldId`, separate action/component registries, and its own public models.
- The all-zero UUID remains the persisted unclaimed-owner sentinel because the current owner schema is UUID-only. `RegionOwnership` is its only production definition and exposes `isUnclaimed`; it is never a SYSTEM actor. Entry-deny system operations persist a nullable creator and retain the typed SYSTEM actor in audit.
- `ActionKey` is the canonical namespaced identity stored in requests/audit. `ActionKey.definitionOrNull` exposes optional built-in `Action` metadata; unknown keys remain representable and auditable but fail closed as unsupported in policy evaluation. The unused core `ActionTypeRegistry` was removed because it had no runtime or test consumers and is not part of the separately published API-client artifact. The API-client `ActionTypeRegistry` and `ComponentTypeRegistry` remain public descriptor catalogs for client integrations only; they do not register server policy behavior or Paper handlers. Making arbitrary module actions evaluable needs a concrete policy/registration contract and is deferred rather than guessed.
- Component descriptors are not runtime handlers. Only `ELEVATOR_PAD` and `TELEPORT_PAD` are `ComponentType` built-ins with active Paper dispatch; core registry reports custom descriptor-only names explicitly. The separate API-client registry is metadata for integrations and does not activate server behavior.
- `PolicyActionRequest`, the `Decision.allowed` Boolean projection, and the Boolean `Decision` constructor have been removed. `NOT_APPLICABLE` remains distinct and callers must handle `DecisionEffect` explicitly.
- `WorldId`/`AreaId` are canonical in Paper runtime resolution, including the active zone command and zone GUI. Legacy world-name fields remain on Region/Zone/Position models, import/configuration, selected REST/client contracts, and mutation/config platform boundaries; those are not canonical runtime IDs.
- Home/visit selection is deterministic for the selected owner's plots, but selection uses per-owner ordering or a full Region UUID rather than a user-friendly alias.
- Historical documents mention Folia; no Folia runtime adapter, scheduler path, or support metadata is active.
